# 每笔预约对应一只宠物和一名员工

一笔预约只为一只犬或猫安排一名具备相应技能的员工，并连续占用该员工的服务与周转时间；多只宠物分别创建预约，同一顾客的不同宠物可以同时服务，但同一宠物不能重叠。服务及周转都必须完整落在营业时间、员工班次和可用区间内。首版容量只由员工技能、班次、停班和已有预约决定，不抽象浴池、房间、设备或多阶段流水线。该边界让预约冲突和状态保持明确，也避免在没有真实门店调研的情况下虚构通用资源模型；顾客可指定员工，也可选择“最快可约”并在预约成功时获得确定的员工分配。浏览和确认页面不占位，只有提交时重新校验并创建成功才占用容量。店长代客预约只能绕过顾客端两小时提前量，不能绕过冲突、技能、班次或停班约束。预约始终保留原计划区间，并以独立的实际占用区间参与冲突约束：取消清空尚未发生的占用，爽约在人工处理时释放后续容量，提前完成或服务终止则在实际结束后保留十五分钟周转再释放剩余容量。
