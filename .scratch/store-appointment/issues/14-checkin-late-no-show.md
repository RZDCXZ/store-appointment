# 14 — 到店核销、迟到与爽约

**What to build:** 让分配员工在正确窗口核销顾客到店，并在迟到后明确选择手动核销或人工标记爽约。

**Blocked by:** 11 — 顾客预约记录、详情、核销码与消息; 13 — 员工今日工作与履约资料边界.

**Status:** ready-for-human

- [x] ST-04 正常核销和 ST-05 迟到处理具备独立、可恢复的路由状态，能从预约详情直接进入。
- [x] 开始前三十分钟至开始后十五分钟允许六位码核销；窗口前任何角色都不能提前核销。
- [x] 首次有效核销将预约从已确认变为已到店，记录员工与实际核销时间，并使核销码失效。
- [x] 相同幂等键或重复核销返回首次核销结果和时间，不产生重复状态历史。
- [x] 开始超过十五分钟且仍已确认时，分配员工或店长可填写原因手动迟到核销。
- [x] 同一迟到场景可改为填写原因并人工标记爽约；系统不会仅因时间流逝自动改变状态。
- [x] 爽约释放处理时刻之后的实际占用，但保留原计划区间，不自动处罚顾客。
- [x] 非分配员工、已取消、已完成、已终止等非法核销或爽约请求返回稳定状态错误。
- [x] 界面清楚区分手动核销与危险的爽约操作，并说明各自容量后果。
- [x] 可注入时钟的 API 测试覆盖窗口起止、恰好十五分钟、重复请求、非法状态和实际占用释放。

## Implementation Notes

- ST-04：`/staff/appointments/:bookingId/check-in`
- ST-05：`/staff/appointments/:bookingId/late`
- API 使用 `DEMO_NOW` 注入时钟，并以员工身份、命令类型和幂等键持久化首次成功结果。
- 爽约只截断实际占用结束时间；原计划与原占用快照保持不变。
