# 22 — 停班与临时闭店进入待处理

**What to build:** 让店长创建员工停班或门店临时闭店，在影响预约时先冻结目标容量并进入待处理，而不是自动破坏顾客安排。

**Blocked by:** 09 — 店长工作台即时看到预约; 21 — 排班模板、草稿、发布与日期例外.

**Status:** ready-for-agent

- [ ] MG-10 停班／临时闭店创建使用独立后台路由，可从排班和工作台直接进入并刷新恢复。
- [ ] 店长可以选择员工停班或门店整体闭店的具体日期与左闭右开时间区间，并填写原因。
- [ ] 提交前显示影响摘要，包括目标容量、受影响预约数量和下一步后果。
- [ ] 无受影响预约时变更可以直接生效；有影响时进入待处理状态并保存影响快照。
- [ ] 待处理区间立即停止接受新预约，已有预约保持原员工、时段和状态，不能被自动移动或取消。
- [ ] 临时闭店作为门店整体事实建模，不创建四条伪造员工停班。
- [ ] 工作台和按员工日历显示待处理风险、遮罩区间和受影响数量，状态与行动提醒视觉不同。
- [ ] 店长不能通过强制参数绕过影响处理直接使冲突容量生效。
- [ ] API 测试覆盖无影响直接生效、有影响待处理、新时段阻断、已有预约保留、区间边界与越权。
- [ ] 创建和状态变化写入追加式审计事实，路由映射记录 MG-10。
