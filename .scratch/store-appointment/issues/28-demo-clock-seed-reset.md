# 28 — 演示时间、完整种子与确定性重置

**What to build:** 让代码审阅者在固定演示时间下反复获得同一组正常与异常场景，并让店长安全推进时间或重置本地数据。

**Blocked by:** 23 — 逐笔处理受影响预约; 24 — 通知失败、重试与预约提醒; 26 — 顾客数据导出与匿名化删除; 27 — 经营看板.

**Status:** ready-for-agent

- [ ] MG-18 演示时间与数据重置使用独立后台路由，可直接访问和刷新恢复。
- [ ] `DEMO_NOW` 作为所有业务“现在”的唯一可选替身；启用时小程序、员工后台和店长后台持续显示演示模式与上海时间。
- [ ] 完整确定性种子包含二十名顾客、约二十八只宠物、过去一百八十天约二百四十笔终态预约及当前／未来十四天约四十笔预约。
- [ ] 三个快捷顾客分别覆盖正常预约、已有未来预约、取消或爽约历史。
- [ ] 重置后固定存在待处理停班、最终失败通知、迟到待处理、待核销、已到店待完成和唯一可争抢时段。
- [ ] 店长可以推进演示时间以触发到期提醒，操作结果和新时间立即反映到所有端并写入审计事实。
- [ ] 数据重置仅在演示模式开放，使用两步确认并明确上传文件、业务数据和旧会话后果。
- [ ] CLI 重置和界面重置使用同一确定性能力；重置清理本地上传并恢复种子素材，同时使全部旧会话失效。
- [ ] 从空数据库连续迁移、重置和启动三次，时段、状态、固定异常和看板结果完全一致。
- [ ] API、Playwright 和脚本测试覆盖时钟推进、提醒触发、重置权限、会话失效、文件恢复和确定性。
