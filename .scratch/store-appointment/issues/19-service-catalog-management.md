# 19 — 主要服务、服务规格与增项管理

**What to build:** 让店长维护门店服务目录，同时保证新配置只影响未来预约、历史预约继续显示原快照。

**Blocked by:** 02 — 后台演示账号与角色路由; 04 — 门店首页与服务目录; 08 — 提交并确认预约.

**Status:** ready-for-agent

- [ ] MG-12 服务管理使用独立后台路由，并为主要服务、服务规格和增项提供清晰关联视图。
- [ ] 店长可以创建和修改名称、适用犬猫、体型、人民币价格、服务分钟数和技能要求。
- [ ] 输入验证拒绝缺失规格、负金额、无效时长、重叠体型语义和不兼容增项。
- [ ] 保存后小程序服务目录和新预约立即使用新配置，已有预约的价格、时长和项目快照保持不变。
- [ ] 被预约历史引用的主要服务、规格或增项只能停用，不能物理删除。
- [ ] 停用项目不再出现在新预约选择中，但历史详情仍能按快照正常显示。
- [ ] 所有创建、修改和停用操作写入追加式审计事实，包含店长、对象、时间和变化摘要。
- [ ] 员工及未登录身份不能访问服务管理接口或路由。
- [ ] 页面覆盖加载、空目录、字段错误、并发配置变化和无权限状态，并符合茸光管理端设计基线。
- [ ] API 与 UI 测试验证新旧预约隔离、停用语义、越权和直接路由刷新。
