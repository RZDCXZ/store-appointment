# 24 — 通知失败、重试与预约提醒

**What to build:** 让店长追踪模拟微信通知的每次发送尝试，并在自动重试失败后人工恢复，同时验证开始前二十四小时提醒。

**Blocked by:** 12 — 顾客取消与顾客改期; 17 — 店长改期与店长取消; 23 — 逐笔处理受影响预约.

**Status:** ready-for-agent

- [ ] MG-15 通知任务列表与详情使用可直接访问和刷新恢复的后台路由。
- [ ] 预约确认、顾客／店长改期、顾客／店长取消和容量影响处理结果均通过事务 outbox 生成通知任务。
- [ ] 模拟微信通道展示待发送、已发送、失败和需人工重试状态，并保存每次尝试时间与结果。
- [ ] 自动发送使用短退避最多重试三次，三次失败后进入工作台风险任务而不是无限重试。
- [ ] 店长可以注入可预测的模拟失败并人工重试；人工重试本身写入审计事实。
- [ ] 通知失败绝不回滚已经成立的预约变化，页面明确说明业务事实仍然有效。
- [ ] 同一通知即使多次尝试也只在顾客消息页形成一条消息，不产生重复对客内容。
- [ ] 开始前二十四小时生成提醒；创建时已经不足二十四小时的预约不补发提醒。
- [ ] API 测试覆盖业务与 outbox 原子性、三次失败、人工重试、消息幂等、进程重启恢复和提醒边界。
- [ ] 路由映射记录 MG-15，Playwright 覆盖失败任务、尝试详情和人工重试。
