# 18 — 预约内容纠正

**What to build:** 让店长在到店核销前修正错误的宠物体重、服务规格或增项，同时重新证明员工技能和连续容量仍然成立。

**Blocked by:** 16 — 店长预约列表与代客预约.

**Status:** ready-for-human

- [x] MG-07 预约内容纠正拥有独立可恢复的路由状态，从预约详情进入并显示当前快照。
- [x] 纠正面板显示体重、体型、服务规格、增项、价格、服务时长和技能要求的前后对比。
- [x] 体重变化自动重新计算体型与规格，不能由店长直接绕过体重规则选择体型。
- [x] 保存前重新校验当前员工完整技能、营业、已发布排班、实际占用和宠物冲突。
- [x] 纠正导致容量不足时拒绝保存，保留原快照并提供换员工、改期或取消的下一步。
- [x] 成功纠正原子更新当前快照与实际占用，追加原值、操作人、原因和新值历史，并通知顾客。
- [x] 更换宠物或完全不同的主要服务不允许通过纠正保存，界面引导取消后新建。
- [x] 已到店或任何终态预约不能纠正服务内容。
- [x] API 测试覆盖体型边界、技能不足、扩大时长冲突、缩短占用、原子失败和非法状态。
- [x] 路由映射记录 MG-07，并验证刷新后前后对比不依赖临时组件状态。

## Comments

- 设计稿页面 → 实际路由：MG-04 预约详情 → `/manager/appointments/:bookingId`；MG-07 预约内容纠正 → `/manager/appointments/:bookingId/correction`；纠正失败后的换员工／改期 → `/manager/appointments/:bookingId/reschedule`；取消预约 → `/manager/appointments/:bookingId/cancel`。MG-07 可直接访问和刷新，始终按 URL 中的预约身份重新读取服务端当前快照。
- 新增纠正选项、保存前预检和原子保存 API。体型与规格只从体重和当前目录重算；事务内锁定预约并复核状态、页面读取事实、内容摘要、员工完整技能、营业、已发布排班、实际员工占用与宠物冲突，数据库排除约束继续裁决最后一刻的并发重叠。
- 成功时在同一事务内更新宠物体重、预约快照和实际占用，保留原计划区间与核销码，追加含原值／新值／操作人／原因的历史、不可变审计和顾客通知 outbox；首次成功或失败均保存幂等结果快照。
- 审查加固：草稿变化会自动防抖预检，并用草稿指纹与请求序号丢弃过期响应；失败结果展示候选快照，确定性失败后生成新的幂等键并要求重新预检；预约事实冲突会在刷新完成前立即作废旧预检。主服务规格、增项、总价与技能分别呈现。
- 最终验证：`pnpm check` 通过（API 120、管理端 62、小程序 66、脚本 3 个测试，并完成格式、lint、类型检查与构建）；管理端完整 Playwright 7/7 通过，审查修复后的 MG-07 定向 Playwright 1/1 再次通过，覆盖直达、刷新、自动预检、保存、详情历史与通知恢复。规格与工程质量双轴最终复审无 P0–P2。
