# 29 — 不可修改审计记录与审计页面

**What to build:** 让店长查看重要业务变化和敏感读取留下的审计事实，同时确保任何应用角色都不能重写或删除这些历史。

**Blocked by:** 17 — 店长改期与店长取消; 18 — 预约内容纠正; 19 — 主要服务、服务规格与增项管理; 20 — 员工账号与员工技能管理; 21 — 排班模板、草稿、发布与日期例外; 23 — 逐笔处理受影响预约; 24 — 通知失败、重试与预约提醒; 25 — 店长顾客与宠物档案及导出; 26 — 顾客数据导出与匿名化删除; 28 — 演示时间、完整种子与确定性重置.

**Status:** ready-for-agent

- [ ] MG-16 审计记录使用独立后台路由，可按操作者、动作类型、对象和时间筛选并刷新恢复。
- [ ] 审计详情展示操作者、时间、对象、动作和安全变化摘要，不泄露密码、会话、核销码明文或完整导出内容。
- [ ] 审计至少覆盖预约创建／改期／取消／纠正／核销／完成／爽约／终止、服务和排班配置、停班与闭店、账号与技能、手机号揭示、导出、删除、通知重试和演示时间推进。
- [ ] 审计记录只允许由受控服务端接缝追加；客户端和普通业务接口不能伪造操作者或时间。
- [ ] 应用不提供更新或删除审计记录的能力，数据库触发器同时拒绝任何更新与删除。
- [ ] 店长只能读取，员工与顾客不能访问门店审计列表。
- [ ] 顾客匿名化后保留不含可识别资料的删除事实，审计页面不能反向暴露已匿名化身份。
- [ ] 数据重置通过重建演示数据库清空审计，不能使用普通删除接口绕过不可修改规则。
- [ ] 真实 PostgreSQL 测试直接验证更新／删除被拒绝，并验证所有要求动作均产生且只产生预期审计事实。
- [ ] 页面覆盖空记录、筛选无结果、局部失败、无权限和大量记录分页，不允许编辑控件出现。
