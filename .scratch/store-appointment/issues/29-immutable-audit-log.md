# 29 — 不可修改审计记录与审计页面

**What to build:** 让店长查看重要业务变化和敏感读取留下的审计事实，同时确保任何应用角色都不能重写或删除这些历史。

**Blocked by:** 17 — 店长改期与店长取消; 18 — 预约内容纠正; 19 — 主要服务、服务规格与增项管理; 20 — 员工账号与员工技能管理; 21 — 排班模板、草稿、发布与日期例外; 23 — 逐笔处理受影响预约; 24 — 通知失败、重试与预约提醒; 25 — 店长顾客与宠物档案及导出; 26 — 顾客数据导出与匿名化删除; 28 — 演示时间、完整种子与确定性重置.

**Status:** ready-for-human

- [x] MG-16 审计记录使用独立后台路由，可按操作者、动作类型、对象和时间筛选并刷新恢复。
- [x] 审计详情展示操作者、时间、对象、动作和安全变化摘要，不泄露密码、会话、核销码明文或完整导出内容。
- [x] 审计至少覆盖预约创建／改期／取消／纠正／核销／完成／爽约／终止、服务和排班配置、停班与闭店、账号与技能、手机号揭示、导出、删除、通知重试和演示时间推进。
- [x] 审计记录只允许由受控服务端接缝追加；客户端和普通业务接口不能伪造操作者或时间。
- [x] 应用不提供更新或删除审计记录的能力，数据库触发器同时拒绝任何更新与删除。
- [x] 店长只能读取，员工与顾客不能访问门店审计列表。
- [x] 顾客匿名化后保留不含可识别资料的删除事实，审计页面不能反向暴露已匿名化身份。
- [x] 数据重置通过重建演示数据库清空审计，不能使用普通删除接口绕过不可修改规则。
- [x] 真实 PostgreSQL 测试直接验证更新／删除被拒绝，并验证所有要求动作均产生且只产生预期审计事实。
- [x] 页面覆盖空记录、筛选无结果、局部失败、无权限和大量记录分页，不允许编辑控件出现。

## Comments

### 2026-08-19 — implementation

- 设计稿页面 → 实际路由：MG-16 审计记录 → `/manager/system/audit?actor=:actor&action=:action&subjectType=:subjectType&subjectId=:subjectId&from=:date&to=:date&page=:page`。页面可直接访问、刷新恢复筛选，支持二十条一页的稳定分页，并区分空记录、筛选无结果、初始失败、局部刷新失败与无权限状态。
- 新增店长只读审计查询 API；服务端以枚举化动作、对象和操作者类型统一追加审计，运行时代码仅保留 `AuditService` 一个 `audit_events` 写入口。列表只从脱敏视图读取，按动作从白名单结构字段生成真实变化摘要，不返回原始载荷。
- 为核销、迟到核销、完成、爽约和终止补齐同事务审计事实；既有预约、服务、排班、停班／闭店、员工、手机号揭示、导出、匿名化删除、通知重试与演示时间动作继续通过统一接缝记录。
- 真实 PostgreSQL 测试验证筛选、分页、角色边界、匿名化读取、非法筛选、无伪造写接口，以及审计事实和脱敏覆盖层的更新／删除都会被触发器拒绝；匿名化视图同时替换操作者与业务对象 ID，避免从语义化 ID 反向识别顾客。管理端页面测试与 Playwright 验证 URL 恢复、只读呈现和安全摘要；仓库级 `pnpm check` 全部通过。
