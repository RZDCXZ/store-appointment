# 10 — 并发争抢与相近建议

**What to build:** 让多个顾客争抢同一时段时只有一笔预约成功，其余顾客不会丢失已填内容，并能选择相近可用安排。

**Blocked by:** 08 — 提交并确认预约.

**Status:** ready-for-human

- [x] 对同一时段并发提交二十个不同竞争请求时，真实 PostgreSQL 中只能存在一笔成功预约。
- [x] 其余请求返回统一时段冲突业务错误，不泄露内部数据库约束名称或堆栈。
- [x] 相同幂等键的重复请求返回首次结果，不被计算为新的竞争者。
- [x] 冲突响应重新计算并返回三至五个相近建议，包含日期、开始、结束和具体员工。
- [x] MP-12 作为真实可恢复页面或 MP-09 的明确冲突路由状态实现，不使用通用错误页。
- [x] 冲突界面保留宠物、主要服务、增项和员工偏好，建议不会未经顾客操作自动替换选择。
- [x] 顾客可以一键选择建议时段或返回其他日期，然后再次经过确认提交。
- [x] 并发测试同时验证员工重叠、宠物重叠和失败请求不产生通知、历史或核销码。
- [x] 小程序组件测试覆盖冲突提示、建议选择、草稿保留和无建议时的恢复路径。
- [x] 路由映射记录 MP-12，并验证刷新后仍能恢复冲突上下文或明确返回时段选择页。
