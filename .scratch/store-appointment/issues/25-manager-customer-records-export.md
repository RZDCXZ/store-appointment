# 25 — 店长顾客与宠物档案及导出

**What to build:** 让店长集中查看顾客、宠物和历史门店服务记录，并按授权范围导出结构化经营资料。

**Blocked by:** 15 — 完成服务、服务终止与追加说明; 16 — 店长预约列表与代客预约.

**Status:** ready-for-human

- [x] MG-14 顾客与宠物档案使用独立后台路由，顾客列表、顾客详情和宠物详情均可直接访问和刷新恢复。
- [x] 店长可按姓名、脱敏手机号和宠物搜索顾客，并查看本人资料、宠物、预约历史与门店服务记录。
- [x] 宠物详情区分顾客护理注意事项和内部门店服务记录，不把两者合并成通用备注。
- [x] 追加更正说明保留原记录、作者与时间，并在顾客档案中按时间顺序显示。
- [x] 店长可按当前预约筛选条件导出 CSV，字段使用领域语言且不暴露数据库内部列。
- [x] 店长可导出顾客与宠物层级 JSON，内容与当前授权范围一致。
- [x] 每次导出写入包含操作者、筛选条件、导出类型和时间的审计事实。
- [x] 员工不能访问门店顾客列表、跨顾客导出或其他员工无关的服务记录。
- [x] 页面覆盖空结果、局部错误、敏感字段、无权限和大于一页数据的可用展示。
- [x] API 与 UI 测试覆盖搜索、历史关联、CSV／JSON 结构、导出审计和越权。

## Comments

### 2026-08-19 — implementation

- 设计稿页面 → 实际路由：MG-14 顾客列表 → `/manager/customers`；顾客详情 → `/manager/customers/:customerId`；宠物详情 → `/manager/customers/:customerId/pets/:petId`。三条路由均通过浏览器直接访问和刷新恢复验证。
- 预约 CSV 入口位于 `/manager/appointments/list`，按 URL 中已应用的日期、状态、员工、主要服务和搜索条件导出；顾客与宠物 JSON 按顾客列表当前搜索条件及店长单门店授权范围导出。
- API 聚焦测试覆盖搜索、档案、历史关联、CSV／JSON 结构、审计事实和员工越权；UI 聚焦测试覆盖分页、空结果、局部错误、脱敏、无权限和下载参数；Playwright 覆盖三条详情路由刷新与两类真实下载。
