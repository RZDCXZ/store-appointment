# 15 — 完成服务、服务终止与追加说明

**What to build:** 让员工在宠物到店后记录正常完成或异常终止，并形成不可被覆盖的门店服务记录。

**Blocked by:** 14 — 到店核销、迟到与爽约.

**Status:** ready-for-human

- [x] ST-06 完成服务、ST-07 服务终止、ST-09 追加更正说明具备独立可恢复的路由语义。
- [x] 只有已到店且当前时间不早于计划开始的预约可以完成；不强制等待预计结束时间。
- [x] 完成时自动生成包含宠物、主要服务、增项、员工和实际时间的结构化门店服务记录。
- [x] 护理标签和内部文字为选填，不强迫员工填写空洞备注。
- [x] 到店后无法继续履约时可进入已终止，原因必填，且不能伪装为已完成、已取消或爽约。
- [x] 提前完成或服务终止后，实际结束加十五分钟周转，随后释放原计划剩余容量；原计划仍保留。
- [x] 服务记录和原说明只读；员工可追加说明，店长可追加更正说明，均保留作者与时间。
- [x] 顾客预约详情只显示实际完成时间，不读取门店服务记录或更正说明。
- [x] API 状态机测试覆盖过早完成、未核销完成、核销后取消、重复完成、终止和容量释放。
- [x] Playwright 覆盖移动员工完成、终止、追加说明以及状态刚变化后的重新拉取。

## Comments

- 设计稿页面 → 实际路由：ST-06 → `/staff/appointments/:bookingId/complete`；ST-07 → `/staff/appointments/:bookingId/terminate`；ST-09 → `/staff/appointments/:bookingId/service-record`。三条路由均可直接访问，并在刷新后从 API 恢复终态或只读记录。
- 数据层新增不可更新、不可删除的门店服务记录，以及只追加的员工说明／店长更正说明；正常完成与异常终止保留原计划快照，并按实际结束加十五分钟截断占用。
- 审查加固：重排后的预约按当前排期释放容量；确认态不可终止且不改变占用；完成与终止都验证占用释放前 1ms 冲突、边界时刻可用；事件仅保留最小履约事实，隐私匿名化清理门店内部文字、说明、历史事件副本与幂等响应快照；追加说明使用新的幂等键，写入成功但回源失败时显式提示并支持重试。
