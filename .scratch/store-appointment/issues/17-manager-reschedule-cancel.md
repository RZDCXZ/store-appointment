# 17 — 店长改期与店长取消

**What to build:** 让店长依据已经与顾客达成的线下约定安全改期或取消预约，并让失败、通知与历史结果清楚可见。

**Blocked by:** 12 — 顾客取消与顾客改期; 16 — 店长预约列表与代客预约.

**Status:** ready-for-human

- [x] MG-06 店长改期使用可直接访问和刷新恢复的路由状态，持续显示原员工与原计划安排。
- [x] 改期面板提供真实可用建议和手动选择，原因必填，并显示新员工、新时间及价格／时长是否变化。
- [x] 店长改期复用同一原子改期能力：新安排失败时保留原占用、核销码和当前事实。
- [x] 改期成功保留预约身份、追加原安排和操作原因、轮换核销码并生成通知任务。
- [x] 店长只可在到店核销前取消，原因必填；核销后界面只能提供完成或服务终止。
- [x] 店长取消释放实际占用、作废核销码、追加历史并生成取消通知。
- [x] 改期和取消要求幂等键，重复请求不生成重复历史或通知。
- [x] 并发状态变化时界面重新读取当前预约并解释变化，不覆盖其他操作者已经成立的事实。
- [x] API 测试覆盖原子失败、核销前后边界、越权、重复请求和通知 outbox。
- [x] 路由映射记录 MG-06 及店长取消确认状态，抽屉／对话框必须由预约详情路由恢复。

## Comments

- 设计稿页面 → 实际路由：MG-04 预约详情 → `/manager/appointments/:bookingId`；MG-06 店长改期 → `/manager/appointments/:bookingId/reschedule`；店长取消确认 → `/manager/appointments/:bookingId/cancel`；核销后的服务终止 → `/manager/appointments/:bookingId/terminate`。变更页面均可直接访问和刷新，并按 URL 中的预约身份重新读取 API 当前事实。
- 店长改期和取消复用共享原子事务能力：在预约行锁内完成容量变更、核销码轮换／作废、追加式历史、审计与通知 outbox；新安排冲突时回滚并保留原占用、原核销码和首次失败结果快照。
- 每次操作携带独立幂等键和页面读取到的单调 `bookingRevision`；服务端在行锁后校验修订号、员工与开始时间。即使安排经历 A→B→A，旧页面的改期或取消也返回 `BOOKING_FACT_CHANGED`，管理端会丢弃旧幂等键、刷新并解释最新事实。
- 验证：初始全仓 `pnpm check` 通过（API 111、管理端 55、小程序 66、脚本 3 个测试，并完成格式、lint、类型检查与构建）；审查修正后定向复验 API 16/16、管理端组件 15/15、管理端 Playwright 1/1，并再次通过受影响包的格式、lint 与类型检查。需求符合性和代码健康度最终复审均无剩余 P0–P2 发现。
