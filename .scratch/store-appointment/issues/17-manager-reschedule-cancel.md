# 17 — 店长改期与店长取消

**What to build:** 让店长依据已经与顾客达成的线下约定安全改期或取消预约，并让失败、通知与历史结果清楚可见。

**Blocked by:** 12 — 顾客取消与顾客改期; 16 — 店长预约列表与代客预约.

**Status:** ready-for-agent

- [ ] MG-06 店长改期使用可直接访问和刷新恢复的路由状态，持续显示原员工与原计划安排。
- [ ] 改期面板提供真实可用建议和手动选择，原因必填，并显示新员工、新时间及价格／时长是否变化。
- [ ] 店长改期复用同一原子改期能力：新安排失败时保留原占用、核销码和当前事实。
- [ ] 改期成功保留预约身份、追加原安排和操作原因、轮换核销码并生成通知任务。
- [ ] 店长只可在到店核销前取消，原因必填；核销后界面只能提供完成或服务终止。
- [ ] 店长取消释放实际占用、作废核销码、追加历史并生成取消通知。
- [ ] 改期和取消要求幂等键，重复请求不生成重复历史或通知。
- [ ] 并发状态变化时界面重新读取当前预约并解释变化，不覆盖其他操作者已经成立的事实。
- [ ] API 测试覆盖原子失败、核销前后边界、越权、重复请求和通知 outbox。
- [ ] 路由映射记录 MG-06 及店长取消确认状态，抽屉／对话框必须由预约详情路由恢复。
