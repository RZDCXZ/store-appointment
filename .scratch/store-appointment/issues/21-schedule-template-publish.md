# 21 — 排班模板、草稿、发布与日期例外

**What to build:** 让店长从每周排班模板生成未来十四天草稿，经确认发布后才向顾客提供容量，并能维护具体日期例外。

**Blocked by:** 06 — 已发布排班形成可预约容量; 20 — 员工账号与员工技能管理.

**Status:** ready-for-human

- [x] MG-08 排班模板与十四天草稿、MG-09 已发布排班与日期例外具有独立后台路由，可直接访问和刷新恢复。
- [x] 店长可以维护每名员工的每周工作日、班次和休息区间；模板本身不形成顾客容量。
- [x] 系统按上海本地日期从模板生成未来十四天草稿，清楚区分草稿与已发布状态。
- [x] 未发布草稿的修改不影响现有可约时段；发布后具体日期班次才参与时段计算。
- [x] 店长可为具体日期设置调班、加班或休息例外，且例外不能超出门店营业规则或产生无效区间。
- [x] 没有容量影响的发布与例外变更可以正常保存，并立即反映到新时段查询。
- [x] 如果修改已发布安排会影响已有预约，不在本票中强制保存，而是返回明确影响摘要并引导容量变更流程。
- [x] 所有模板、草稿、发布和例外变化写入追加式审计事实。
- [x] API 测试覆盖十四日日期边界、周一闭店、模板不形成容量、发布生效和日期例外覆盖。
- [x] 页面持续使用不同视觉语义区分模板、草稿和已发布排班，并覆盖空态、校验错误、局部失败和无权限。
