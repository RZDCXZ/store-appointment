# 23 — 逐笔处理受影响预约

**What to build:** 让店长对待处理停班或闭店影响的每笔预约逐一换员工、改期或取消，全部解决后才使容量变化正式生效。

**Blocked by:** 17 — 店长改期与店长取消; 20 — 员工账号与员工技能管理; 22 — 停班与临时闭店进入待处理.

**Status:** ready-for-human

- [x] MG-11 受影响预约处理使用独立后台路由，可从工作台风险任务进入并刷新恢复进度。
- [x] 页面持续显示容量变更摘要、完成进度和每笔预约的宠物、顾客、服务、原员工与原时间。
- [x] “同时间换员工”只显示覆盖全部技能且拥有完整服务与周转容量的员工。
- [x] “改期”复用原子店长改期与相近建议，要求原因；失败时原安排和处理进度不变。
- [x] “取消”复用店长取消，要求原因并预览将产生的通知。
- [x] 每笔处理成功后保存结果摘要、操作者、原因与关联预约历史，并保持可追踪。
- [x] 全部受影响预约处理完成后，停班或闭店才转为生效；系统不提供强制生效入口。
- [x] 尚未完成的待处理员工停班可以撤销并恢复原容量，已经成立的预约处理结果不能被静默回滚。
- [x] API 测试覆盖三种处理方式、部分完成、并发处理冲突、最终生效、撤销和新容量阻断。
- [x] Playwright 验证完整逐笔处理流程、进度恢复、直接路由刷新和工作台风险消失。
